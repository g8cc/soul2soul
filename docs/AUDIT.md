# AUDIT.md — 审计规范（把"我仔细看过"变成机器可核查的约束）

## 0. 为什么有这份文件

v0.2.44 悬浮球丢失复盘：此前已做多轮"稳定性审计"（STABILITY-AUDIT.md），甚至修过同族 bug
（c107105 m5：自画层 addView 失败不还球），却仍漏了「完成」按钮退出画笔后入口球整场消失
这种一眼可见的不对称。复盘结论：

- 审计覆盖是口头承诺——审了 N 遍，没人能说出每遍走了哪些格子；
- 镜头固定在"稳定性"（崩溃/并发/数据），"功能性状态丢失"根本不在维度清单里；
- 逐案反应式修复：撞见一个 hide 路径修一个，从不穷举 restore 路径；
- Service 窗口接线类代码 JVM 跑不了，"配锁定用例"的要求在这类代码上自然失守。

本文件规定四条约束。**原则：能变成 gate 的绝不留给人眼；变不成 gate 的，至少变成看得见的空格。**

## 1. L1 状态机矩阵：审计的交付物是表，不是报告

- 每个有模式/状态的 UI 功能，在 `docs/AUDIT-MATRIX.md` 有一张矩阵：行=状态，列=事件，
  格子=预期结果+判定（`PASS` / `GAP` / `⬜待填` / `N-A`）。
- 每轮审计先补空格、再复核格子对错；**矩阵里的 `⬜` 和 `GAP` 就是审计欠债，t0 会打印数量**。
- 新功能上线时矩阵必须先于"我觉得测过了"存在：入口×出口不成对，就是 bug 温床
  （丢球事故 = (自画开启, 点完成) 这一格从没人填过）。

## 2. L2 不变式 gate：修一条踩坑 = 登记一条机器可查规则

每条真机踩坑提炼成不变式，写进下列两处之一，否则不算"已锁定"：

- **t0 静态守卫**（`scripts/test.sh` t0_static，grep 类禁式/配对，先例：INPUT_SERVICE
  误 cast、主源码禁 java.nio.file、悬浮层 addView 必配 removeView）；
- **t1 源码扫描测试**（结构类配对，先例：OverlayBallWiringTest——每个 `exitDoodle()`
  调用点后必须紧跟球位恢复）。

自检法：把修复回滚，用例必须变红；不会红的用例没有资格存在。
纯逻辑能抽就抽成可注入函数配真单测（AGENTS.md 既有约定），抽不动的才用源码扫描兜底。

## 3. L3 固定维度清单：每轮过全维度，不靠个人发挥

每轮审计对每个功能至少过这 5 个维度，缺哪个维度就在矩阵里记哪个维度的 `GAP`：

1. **恢复对称性**：每个 hideX/removeX/dim，穷举所有触发路径，确认都有 restoreX；
2. **生命周期与配置**：旋转、分屏、后台被杀、START_STICKY 重启、进程重建；
3. **权限中途收回**：悬浮窗/无障碍/麦克风在会话进行中被系统或用户撤销；
4. **多入口多出口配对**：所有入口 × 所有出口两两组合（点球/摇一摇/按钮/通知/深链）；
5. **降级与老机型**：minSdk 23 / Android 7 字体与 API、旧版本 App 对新协议字段的容忍。

## 4. L4 真机场景脚本：JVM 够不着的格子必须留痕

- 涉及窗口接线、触摸分发、手感的格子，落 uiautomator 脚本进 T4；
- T4 跑不了就如实标 SKIP，**SKIP 不等于通过**（既有约定），发版说明必须写；
- 双端真机验证（#30/#38/#43）积压的格子优先补——丢球 bug 真机 20 秒必现。

## 5. 复盘规则（每次真机 bug 关闭时执行）

1. 矩阵加一行/填一格，注明所属 L3 维度；
2. 按 L2 登记 gate（t0 或 t1），提交信息带"锁定"字样；
3. 若该 bug 属于"审计过却没查出"，在 STABILITY-AUDIT.md 追加一行：漏检原因 + 本文件哪条
   约束本可拦住它。

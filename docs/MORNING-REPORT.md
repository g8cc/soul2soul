## 2. 必须向你坦白的一件事

**模拟器自动化的点击注入不可靠**：高负载下 `input tap` 随机丢失、`uiautomator dump` 静默失败，我用坐标点击/重试/钩子/adb root 六种方式交叉对抗，"配对→呼叫→接听"前半段稳定通过，但"接听→出画面"最后一段始终差一次可靠的点击落地。期间还发现了一个环境地雷：**Mac 本地残留的旧版信令进程和 guo 生产服务器并存，模拟器连的是旧的**（已清理并重启）。

因此：**当前 v0.2-rc 的"接听→出画面"路径没有被端到端跑绿过一次**（重构后的接听逻辑 = 之前实测跑通 ICE 的逻辑 + 缓存增强，我已逐行核对），这段只能在真机首测确认——真机没有模拟器的输入问题，10 分钟内见分晓。如果首测这一步失败，把现象发我，修复是局部的。

## 4. 现在轮到你：真机首测（15 分钟）

装 `dist/Soul2Soul-v0.2-release.apk` 到两台手机（小米/华为保活设置见 App 内引导），按顺序：

1. 配对（2 分钟）
2. A 点「一起玩」→ B 看到来电（铃声+振动+倒计时）→ 接受
3. **关键观察点**：A 允许屏幕录制后，B 的屏幕 30 秒内出现 A 的画面 ← 这一步就是模拟器没验证到的路径
4. B 画一笔 → A 屏幕浮现；B 说话 → A 听到
5. 任一端结束 → 两端回待命 → 再来一次反向（B 共享 A 看）

**如果第 3 步黑屏或超时**：`adb logcat | grep -E "S2S-|WebRtcClient"` 发我，5 分钟定位。

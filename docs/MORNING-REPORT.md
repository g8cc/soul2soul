# 🧹 深度优化轮 v0.2.5（2026-09-29）

> 全库精读审查（App 20 文件 + 信令服务端）后的系统性优化：4 个真机可复现 bug + 4 处服务端健壮性（含 1 个测试抓出的崩溃隐患）+ 3 处体验/内存打磨。

## O1. 本轮修了什么

| 项 | 根因/内容 | 影响面 |
|---|---|---|
| **观看端本地笔迹边写边消失** | 本地层淡出仍从"落笔"计时（T2 修复只改了共享端）：一笔写超过 2 秒，前半段先淡出。已改为"收笔后淡出" | 体验 P0 |
| **落笔信号丢失 → 整笔凭空消失** | 容忍丢包通道丢了 `s` 消息时，后续笔点找不到笔画被整条丢弃。共享端已加自愈：凭笔点现场建笔；`s` 重发幂等去重 | 体验 P0 |
| **通知栏"静音"是系统全局关麦** | `AudioManager.isMicrophoneMute` 会关掉整台手机所有 App 的麦克风。改为轨道级 `audioTrack.setEnabled(false)`——只静音本会话上行 | 副作用 P0 |
| **系统撤销录屏授权 → 黑屏挂着** | `MediaProjection.Callback.onStop` 原为空实现。现在授权被撤销即结束会话（reason=projection_stopped） | 韧性 P0 |
| **服务端巨包处理可崩进程** | 加 maxPayload 时对抗测试抓出：`ws` 拒收巨包默认抛无人监听的 `error` 事件 → **未捕获异常直接崩整个信令进程**（生产同样会炸）。已加连接级 error 兜底 | 稳定 P0 |
| 配对码表慢性内存泄漏 | 过期码从不删除；新增每 60s 清扫 + 每设备最多 1 个有效码（申请新码即撤销旧码） | 内存 P1 |
| pair.request 无限速 | 任何连接可无限申请配对码（码表 DoS）；现每设备 5 秒 1 次 | 防滥用 P1 |
| WebSocket 无消息上限 | 现 256KB 封顶（SDP offer 约 50KB），巨包在传输层断连不进业务代码 | 加固 P1 |
| **RTT 降级不可恢复** | 弱网降到 960 后永不回升。现引入"用户意图档位"：RTT 持续 <150ms 20 秒即回升（HD 开过 1920 的回升到 1920） | 体验 P2 |
| SignalBus 缓冲 64 可能丢 SDP/ICE | ICE 风暴下 DROP_OLDEST 丢一条 offer 就白屏。扩容 512 | 韧性 P2 |
| 录屏授权 Intent 驻留静态字段 | 呼叫撤销/超时/启动服务后即用即清；顺带删除服务侧从未读取的 resultCode 冗余传参 | 内存/安全 P2 |
| 测试基建 | 服务端数据文件支持 `S2S_DATA_FILE` 隔离（对抗测试不再污染开发配对数据）；`PAIR_CODE_TTL_MS` 可环境变量覆盖 | 基建 |
| 发版脚本 version.json 引号 bug | `ssh "printf …"` 层层转义把 versionName 写成 `""0.2.5""`（非法 JSON）→ App 检查更新 `JSONObject()` 解析失败被 runCatching 吞掉，更新渠道静默失效。脚本已改为 heredoc 写入 + 写后 JSON 校验；远端清单已重写并公网验证解析通过 | 发布 P0 |
